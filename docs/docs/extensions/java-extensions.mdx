# Java extensions

Load compiled [WireMock extensions](https://wiremock.org/docs/extending-wiremock/) – transformers,
matchers, admin routes – from JARs. No JDK needed.

| Method | Registers |
|--------|-----------|
| `withExtensionJar(jar)`, `withExtensionJars([...])` | A JAR, or every `*.jar` of a directory – any [file source](../guides/file-sources.mdx) |
| `withExtension(ext)`, `withExtensions([...])` | A fully qualified class name – or a [TypeScript extension](./typescript-extensions.mdx) |
| `withExtensionOptions({ scanning, verifyClassNames })` | How extensions load |

## Control how extensions load {/* #extension-options */}

`withExtensionOptions()` takes `WiremockExtensionOptions`:

| Option | Default | `false` |
|--------|---------|---------|
| `scanning` | `true` | Ignore `META-INF/services`: only named classes load |
| `verifyClassNames` | `true` | Skip the start-up check that each class is in a registered JAR – for classes a custom image provides |

## Validation rules {/* #rules */}

Checked before anything starts:

- JARs exist and end in `.jar`; names are unique – rename with `{ file, name: "other.jar" }`.
- Class names are fully qualified: `com.acme.MyTransformer`.
- On `start()`, each class is in a registered JAR or WireMock itself:

```ts file=extensions/extensions.test.ts#start-check
```

- `withCommand()` does not set `--extensions` or repeat an extension's option.
- JARs target Java 11 (WireMock 3's runtime). Custom images keep `/var/wiremock/extensions`.

Start-up failures: [troubleshooting](../reference/troubleshooting.mdx#errors-when-starting).
